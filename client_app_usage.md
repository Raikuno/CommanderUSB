# Usage
The client application will operate passively; it does not provide any interface beyond the installer. Any action or configuration change must be performed from the server.<br>
The client application is mainly responsible for two essential tasks: controlling whether USB drives are inserted into the machine and sending information to the server about the machine's status.<br>
USB drive usage control is achieved by preventing them from mounting automatically, which normally occurs in a Windows environment. This is done by modifying the Windows registry entry: Computer\HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\USBSTOR\Start. This value usually has a default value of 3, which enables automatic mounting of USB drives. CommanderUSB changes this value to 4, which prevents USB drives from mounting automatically. The application continuously checks the Windows registry so that if any modification occurs or a USB drive is mounted, it will once again block the value in the Windows registry, unmount all USB drives, generate a log with the previous state information for the security measures application, and send all logs stored in the dedicated event log channel for the Windows Event Viewer.<br>

Regarding the logs generated by the application, these are stored in a dedicated entry in the Windows Event Viewer, as mentioned earlier. This decision was made due to the security this tool provides, because a normal user cannot usually create a log in the application's name or delete existing logs, as that would require deleting all generated records, making it obvious in the server application interface that tampering has occurred. Similarly, log storage is temporary and serves as an alternative security measure in case the machine cannot connect to the server for any reason. Every time a log is generated, whether due to a security violation caused by a malicious user or a regular periodic record, all stored entries on the machine are sent to the server, and the relevant Event Viewer entry is cleared to avoid storing obsolete data.<br>

<br><br>

All values that require persistence to ensure the application works correctly, i.e., the application configuration, are stored in the Windows registry at: Computer\HKEY_LOCAL_MACHINE\SOFTWARE\UsbCmmdr.
The stored values are as follows: the server IP address, the server socket port, and the frequency at which regular status logs are generated.
The port and IP are stored when the application is installed, whereas the frequency of regular logs is stored the first time the application starts.
